# 愿景定义

**没有单一厂商中心化托管模型/Agent；算力来自全球大量异构闲置终端（家用PC、手机、边缘设备）；Agent可以独立部署、互相发现、自主协作；模型权重、Agent状态、任务分散在网络节点，类似互联网去中心化，而不是集中在大厂机房**。

它和现在的体系有本质区别：
现在：用户→大厂API，大模型跑在厂商GPU集群；
分布式Agent网络：Agent程序、模型分片、推理任务分布在无数普通人闲置设备，节点随时上线下线、异构、**节点本身不可信**。

整套体系是多领域交叉，下面按模块拆解需要跟进学习的技术，再区分【现在就能上手实践】和【前沿科研待突破】，最后讲核心瓶颈和学习路线。

## 一、模型与分布式推理层（最底层基础）

核心问题：大模型不能整体塞进单台家用终端，要拆开来，在异构设备上跑推理/少量微调。

1. **模型轻量化技术**
    - 量化（GGUF/AWQ/GPTQ）、稀疏化、知识蒸馏；把大模型压缩到可以在消费级显卡、CPU本地运行。llama.cpp 是这个方向最典型工具。
    - MoE（混合专家模型）：把模型拆成多个“专家”，不同专家部署在网络不同节点，Agent按需调用专家节点，不需要加载完整大模型。
2. **Split Inference（模型分片推理）**
    将模型计算图拆分成多段，前几层在节点A计算，中间激活值传给节点B计算后几层。解决单台设备显存不足，跨多台闲置终端合跑大模型。难点：不稳定家庭带宽、异构硬件带来的延迟抖动。
3. **异构推理运行时**
    ONNX Runtime、Wasm-WASI 神经网络算子：Wasm非常关键，Agent和模型算子打包成wasm，Windows/Mac/Linux/浏览器跨设备可移植，不需要适配不同系统。
4. **分布式微调：联邦学习 FL**
    > 这个是去中心化场景的核心，**不再收集所有人原始数据上传到中心服务器训练**。
    - 联邦微调：每个终端用本地数据，只更新模型局部参数/梯度，只上传梯度，原始数据保留在本地；网络聚合多方梯度更新全局模型。
    - 挑战：节点异构、通信开销、梯度投毒，需要鲁棒梯度聚合算法。

> 补充：联邦推理也是分支，多个节点协同完成一次推理，原始输入不离开本地。

## 二、P2P网络与分布式算力调度层

中心化云用K8s管理稳定服务器；而你的场景是**动态P2P网络，节点随时关机下线、NAT内网环境、算力差异巨大**。

1. **P2P基础网络**
    libp2p（IPFS底层）：节点发现、NAT穿透、点对点消息传输、中继。解决家庭设备大多在内网，无法直接被外部访问的问题。
2. **去中心化资源发现与算力编排**
    - 节点能力声明：每个终端上报可用算力、显存、带宽、支持模型类型；
    - 任务拆分与调度器：把Agent复杂任务拆成独立子任务，自动匹配算力节点；节点掉线自动迁移任务。
    - 区别：不是中心化调度器，调度逻辑本身也分布式。
3. **内容寻址存储（IPFS等）**
    模型权重分片、Agent程序包、记忆数据用哈希寻址，而不是域名/中心化服务器地址。模型文件不再托管在厂商oss。

## 三、分布式AI Agent核心技术

现在流行的Agent（LangGraph、AutoGen）大多是**单体Agent，运行在云服务器，调用中心化LLM API**；分布式Agent完全不一样：

1. **Agent自治与本地优先架构**
    Agent优先在本机完成推理；本机算力不足时，才向P2P网络请求其他节点算力。Agent本体（规划逻辑、工具调用代码）打包，可部署在任意节点。
2. **多Agent P2P协作协议**
    Agent之间不是调用中心API，而是点对点通信：能力注册、任务协商、子任务委托、结果回传。
    - Agent能力发布：类似互联网网页，Agent对外声明自己能做什么（代码、摘要、检索）；网络里其他Agent可以检索发现能力。
3. **分布式Agent记忆**
    Agent短期上下文、长期记忆向量库不能放在中心数据库。需要**去中心化向量数据库、P2P向量检索**。记忆分片存储在分布式存储网络。
4. **任务规划与容错**
    子任务失败自动重试；多副本任务，用来对抗恶意节点返回虚假结果。

## 四、隐私与可信计算（最大瓶颈）

P2P网络里算力提供者是陌生人，**你不能信任节点**：可能篡改推理输出、窃取输入数据、伪造算力贡献。

1. **隐私保护技术**
    - 差分隐私：联邦学习中给梯度加噪声，防止别人从梯度反推出原始数据；
    - 安全多方计算 SMPC：多个节点共同计算，各方看不到别人原始输入；缺点：计算开销极大；
    - 同态加密 HE：加密数据上直接做推理，解密后得到结果；目前性能还无法跑大模型；
    - TEE可信执行环境：在CPU硬件加密隔离区跑推理，保证代码和数据不被节点操作系统窃取；但依赖硬件，有漏洞风险。
2. **可验证计算 / ZK零知识证明**
    非常关键：节点执行完AI推理/计算，生成零知识证明，**证明它正确完成了计算，不需要暴露输入输出**。用来验证节点有没有偷懒、伪造结果，是算力激励的基础。
3. **鲁棒性与防投毒**
    恶意节点会上传污染梯度（联邦学习）、返回错误推理结果。需要：结果冗余校验、异常梯度检测、节点声誉系统。

## 五、去中心化存储

Agent记忆、向量分片、模型权重分片需要分布式存储：IPFS、Filecoin等。重点不是单纯存文件，而是支持**P2P向量检索**。

## 六、激励、声誉与治理系统

如果希望普通人自愿贡献闲置算力，必须一套机制，不一定是代币，但需要：
1. **算力贡献计量**：量化节点提供多少算力、完成多少任务；
2. **节点声誉系统**：根据历史结果正确性、稳定性打分；声誉低的节点少分配任务；
3. **协议治理**：没有中心公司，网络协议、规则如何迭代升级，避免分裂；
4. 博弈论：多参与者（算力提供者、Agent使用者）之间的博弈，防止恶意薅资源。

> 注意：区块链是可选组件。可以用链存ZK证明、声誉账本，AI推理计算本身不上链（链计算太慢）。很多P2P算力网络是【P2P计算 + 链做记账/证明】，不是链上跑大模型。

# ✅ 分两类：【短期可上手学习】vs【前沿科研方向】
## 短期（现在就有开源项目可以动手实践）
1. 本地LLM：llama.cpp，GGUF量化，本地推理；
2. Agent框架：LangGraph、AutoGen，理解Agent规划、记忆；后续改造为P2P通信；
3. P2P网络：libp2p、IPFS，做节点发现、文件分发；
4. Wasm + 轻量模型：在浏览器/终端跑模型；
5. 联邦学习基础：Flower（联邦学习开源框架）；
6. 向量数据库基础（本地）：作为学习去中心化向量检索的铺垫；
7. Split inference 原型项目。

## 中长期（科研原型阶段，大规模工程落地还很远）
1. ZK 可验证大模型推理；
2. SMPC大规模神经网络计算；
3. 大规模异构节点联邦微调；
4. 去中心化多Agent涌现行为管控；
5. 大规模P2P向量检索。

# ⚠️ 这个架构的几个核心固有难题（理解它，就知道技术重心在哪）
1. **节点高度动态异构**：家用电脑随时关机，算力/带宽不稳定；中心化云服务器是稳定可控的。
2. **不可信节点问题**：中心化场景信任云厂商；分布式场景所有节点都是不可信，必须用冗余、ZK证明做验证，带来巨大开销。
3. **通信开销爆炸**：分片推理、联邦学习需要大量传输张量/梯度，家用带宽是瓶颈。
4. **涌现风险**：大量自治Agent在无中心管控下互相交互，可能出现不可预期、有害的涌现行为，很难审计。
5. **性能代价**：隐私、可信验证都会带来算力开销，会比中心化API贵、慢。

# 📌 学习路线建议（按你的偏好选）
### 路线A：偏应用/Agent开发（最容易入门）
本地LLM → Agent框架（LangGraph）→ libp2p P2P通信 → IPFS存储 → 尝试做小型多Agent点对点交互原型；再尝试接入split inference。
目标：开发分布式Agent应用，理解网络中Agent如何互相发现、委托任务。

### 路线B：偏模型底层/分布式推理
模型量化、llama.cpp → split inference → Flower联邦学习 → 异构硬件推理优化。
目标：研究如何把模型拆到多个终端协同推理。

### 路线C：偏可信与隐私方向
密码学基础（ZK基础）、差分隐私、TEE，研究如何验证P2P节点计算真实性。

# 补充：现有原型项目参考
Golem Network、Render Network、Fetch.ai、Prime Intellect，还有一些FL开源项目，都在探索分布式算力+Agent，但**都还不是你描述的完整大规模百花齐放网络，属于早期实验原型**。
